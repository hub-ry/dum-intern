How it works

Pair, and keep track of what you want to learn.

Pair

Open Pair. The project README covers its offline behavior, message drafts, and theme settings.

1. Open your folder

  • Open Skill tree and sign in with your GitHub username to save topics.
  • Put the login code, alone, in a public gist whose file is named dum-login. Check it to prove the account is yours, then delete the gist. If GitHub OAuth is configured, you can use that instead.
dum/
  goal.md
  tree.json
  readings/     one assignment per block
  builds/       each stack you save

The starting folder is template/dum. For workspace selection and getting papers onto the server, see the project README.

2. Grow your skill tree

  • For adding individual learning topics, see the project README.
  • For a larger outline, open Workspace tools → Outline a goal. Leave the outline empty for a five-block starter tree, or write the blocks yourself, one per line. Two spaces indent a child.
  • Workspace tools also holds saved builds and hints. Its goal selector chooses which goal those tools use.

3. Read a block

  • Each reading is a LaTeX article with \usepackage{learn}, the format used at learn.ryhub.dev.
  • Open your Dum folder in Cursor. Use the repo's dum-paper skill to write and compile the paper on your machine, using your Cursor account.
  • Put the PDF in readings/pdf/. Until it is there, the block has nothing to read. Hub doesn't write or compile the paper.
  • Read the PDF inside your login. Reaching the last page unlocks the block. There is no quiz or work to submit.

4. Skip what you already know

Swear a block in a sentence. It unlocks without the reading, even if its parent is still locked. The tree marks it sworn so you can distinguish it from a block you read.

5. Stack a build

Give the build a name. Select unlocked blocks and put them in the order you want. Locked blocks cannot be stacked. Saving a build records the stack; it doesn't generate a finished program.

Storage and privacy

  • The site, account workspaces, and reader run on hub. Paper generation runs in your own Cursor session.
  • Your folder is not published automatically. Putting it in a public repo is your choice.
  • Read or sworn describes how a block was unlocked, not a measurement of mastery.
