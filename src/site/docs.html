How it works

Dum is a skill tree for one goal at a time. You unlock a block by reading it. You build by stacking the blocks you unlocked.

Sign in

Sign in from your Dum with your GitHub username. Dum gives you a code. Put that code, alone, in a public gist whose file is named dum-login, then check it. That proves the account is yours. Delete the gist afterwards. If GitHub OAuth is configured on hub, the GitHub button is there too.

The folder

Each account has a workspace on hub. The root is a folder named dum unless you assign another one from the Folder tab. On hub, the owner can point Dum at any directory under their home directory.

dum/
  goal.md
  tree.json
  readings/     one learn-format assignment per block
  builds/       each stack you saved

The base of that folder is template/dum in hub-ry/dum-intern. Fork the repo if you want your own copy in git. The site reads and writes the folder it has on hub. It does not keep a second copy of the tree.

Goals and the tree

Name a goal and say what you want to be able to build. Leave the outline empty and Dum drafts five blocks: what this is, the smallest piece, checking it by hand, the next piece, and stacking the pieces. Or write the blocks yourself, one per line, indenting a child with two spaces.

Readings

Each block is a LaTeX article with \usepackage{learn}, the same style as learn.ryhub.dev. You read the PDF inside your login. Reaching the last page unlocks the block. There is no quiz and nothing to submit.

Hub does not write the paper and does not compile it. Open the Dum folder in Cursor and ask it to write the paper for that block. The dum-paper skill in this repo does it on your machine, with your Cursor account, then you commit the PDF. Until that file is in readings/pdf/, the block has nothing to read.

Swearing

If you already know a block, swear it in a sentence. It unlocks without the reading, including a block whose parent is still locked. The tree marks it sworn, so a stack can tell a block you read from a block you skipped.

Builds and hints

A build is a name plus unlocked blocks in an order you choose. A locked block cannot be stacked. Hints lists two things: readings you can open now (a locked block whose parent is unlocked, or a root), and stacks made from the unlocked chains you already have.

Where it runs

The site and the folders live on hub. That is storage and the reader. Writing a paper spends the Cursor account of whoever has the folder open. Nothing in the folder is public unless you put the folder in a public repo yourself.
