Installation

Have your AI build it ↓

There's no public release of this version yet. You build Dum on the Mac that will run it, in the order below. Test builds also come out of the desktop macOS workflow on pushes to main; only signed-in GitHub accounts can download them, and the older test prerelease on the releases page predates zones and doesn't match these docs.

1. Prerequisites

  • macOS 13 or later, on Apple Silicon or Intel. Voice needs macOS 14 or later on Apple Silicon; everything voice does also works from the keyboard.
  • Node 22.6 or later: brew install node.
  • For voice, three more things on the build Mac: the full Xcode from the App Store (Command Line Tools aren't enough), then sudo xcode-select -s /Applications/Xcode.app/Contents/Developer && sudo xcodebuild -license accept; cmake, brew install cmake; and Rust through rustup with rustup target add aarch64-apple-darwin. Homebrew's rust has no rustup and the build refuses it.
  • Network during the build (it fetches whisper.cpp and Swift packages) and once more when you download a speech model.
  • A backend to power Dum: your own Anthropic API key for Claude, or models running on your Mac in Ollama or LM Studio. See who powers Dum.

The app carries its own Claude Code. You don't install anything else to use Claude.

2. Build

git clone https://github.com/hub-ry/dum-intern
cd dum-intern
npm install && npm run desktop:mac

The app lands at release/mac-arm64/Dum.app, with a DMG beside it. If prepare-dictation stops, its message names the missing tool from step 1. Every build connects Claude with your own API key only.

3. Install

Copy Dum.app to /Applications. The build is ad-hoc signed and not notarized, so the first time, right-click it and choose Open. Dum is a small floating circle; there's no Dock icon and no menu bar icon. Drag the circle wherever you like.

4. First launch

  1. Dum's window opens by itself and asks What are you trying to learn? The answer becomes your first zone. Nothing is sent to a model for this.
  2. macOS asks for Screen Recording permission, for Dum's look. If you say no, Dum looks at app switches and saved files only.
  3. Click Who powers Dum? and pick a backend and three models: Dum's model, the helper and the look model. For Claude, paste your Anthropic API key. The key has to be scoped to a workspace: a key created outside one fails with must include the anthropic-workspace-id header. Create it at console.anthropic.com inside a Workspace, or use a key that already belongs to one.
  4. Dum and the Wizard then start goal alignment for your first zone. From now on, click the circle, or press ⌘⇧D from anywhere, to open or hide Dum's window.

5. Verify for pictures, if you pick Haiku

Dum sends screenshots only to a model whose resolved id it has verified for pictures. opus and fable are verified out of the box. For any other Claude model, haiku included, Settings → Agent shows Verify for pictures (one small call) next to that role. Press it: Dum sends one 2×2 PNG and the line Reply with the single word OK. to that model on your key. Success records the resolved id in ~/.dum/verified-models.json and the look starts sending frames. Failure records nothing and the reason stays next to the button. Dum refuses to verify while it's in the middle of a request; finish or Stop it first.

6. Set up voice

Voice exists only in the packaged app on Apple Silicon. No speech model is bundled; you pick and download one the first time.

  1. Launch Dum. The voice helper starts with it, because a voice shortcut (Control+Option+Space) is set by default. Nothing prompts yet.
  2. Open Dum and go to Settings → Set up voice. The Dum voice setup window opens.
  3. Microphone: macOS asks the first time the window opens. The prompt is attributed to Dum. Click Allow. If you clicked Don't Allow, go to System Settings → Privacy & Security → Microphone, turn on Dum, and reopen Set up voice.
  4. Speech model: pick one and wait for the download. Whisper Small (574 MB) is the quickest to try, Whisper V3 Large (1.6 GB) the most accurate, Parakeet v3 the fastest at run time. The row becomes selected when the download finishes. Close the window.
  5. Check the voice line in Settings reads Hold the voice shortcut and talk…. Any other line names the step still missing: microphone, model or shortcut.
  6. Open a zone with an empty draft. Hold Control+Option+Space, speak, release. The bubble shows Listening…, then Transcribing…, then your text. A draft that isn't empty refuses the press; clear it first.
  7. The transcript is in your draft only. Send it with ⌘⇧Return, or open Dum and edit it. Voice never sends by itself.

Speech models live in ~/Library/Application Support/com.dumintern.opensuperwhisper/ (whisper) or ~/Library/Application Support/FluidAudio/Models/ (Parakeet). Recording and transcription after that are local; the helper needs network again only if you pick another model. A recording stops after two minutes.

Known limits: if another app owns the hotkey, macOS refuses it silently and Dum still reports the shortcut as set; the symptom is a press that does nothing and no bubble. Change the Hold-to-talk shortcut in Settings. Intel Macs and macOS 13 get keyboard-only voice.

Troubleshooting

  • "must include the anthropic-workspace-id header." Your Anthropic key isn't scoped to a workspace. Dum doesn't add that header. Create a key inside a workspace (console.anthropic.com → Workspaces) and paste that one in Settings → Agent.
  • "No pictures: … isn't verified for pictures yet." The look model's resolved id isn't verified, so the look runs on text alone. Settings → Agent → Verify for pictures (one small call) next to the look model.
  • The circle shows the voice-error badge. Open Settings and read the voice line, then Set up voice again. A stopped helper restarts on the next press or setup.
  • "The voice helper stopped" right after launch, from a DMG you downloaded through a browser. Clear quarantine: xattr -dr com.apple.quarantine /Applications/Dum.app, then open Dum again.

Developing without voice

npm run desktop            # build Dum and launch it from the checkout

npm run desktop runs without Dum's two native helpers, so there's no voice, no noticing app switches, and Esc can't hand focus back to the app you were in. It also starts on Linux, for development and testing only; Dum is a Mac app.

Let a terminal LLM build it

Prefer to paste one instruction into the terminal agent you already use? This walks it through building the packaged Mac app from source, checks each step, and stops when it needs you. The steps you do yourself afterwards: right-click → Open, the Screen Recording and microphone prompts, your API key, the speech model download.

paste into your terminal LLM 
Set up Dum from https://github.com/hub-ry/dum-intern for me: build the packaged Mac app from source with `npm run desktop:mac`.

Work one step at a time. Check the result before continuing. Ask me before:
- using sudo or installing anything system-wide (including Xcode, cmake, rustup, Node)
- accepting the Xcode license
- opening a browser for any sign-in or completing 2FA
- entering, copying, storing, or relaying passwords, API keys, one-time codes, recovery codes, or security keys
- writing outside the folder I give you
- changing an existing project or deleting anything

1. Check that this is a Mac on macOS 13 or later, and check my Node version (22.6 or later is needed). If it isn't a Mac, tell me Dum is a Mac app and stop. If Node is missing or too old, ask me before installing it.
2. If this is an Apple Silicon Mac on macOS 14 or later, voice can be built too. Check for the full Xcode (`xcodebuild -version`), `cmake`, and `rustup` with the `aarch64-apple-darwin` target. Tell me what's missing and ask me before installing any of it. Homebrew's `rust` package won't do; it has to be rustup.
3. Ask where I want the repository. Clone it there if it is not already present.
4. In the repository, run `npm install`.
5. Run `npm run desktop:mac`. If `prepare-dictation` stops, show me its message; it names the missing tool. When it finishes, confirm `release/mac-arm64/Dum.app` exists.
6. Copy `release/mac-arm64/Dum.app` to `/Applications` only if I say so. Do not open it yourself.
7. Tell me what's left for me to do, then stop: right-click Dum.app and choose Open the first time; answer the Screen Recording prompt; answer "What are you trying to learn?"; click "Who powers Dum?" and pick a backend; in Settings → Set up voice, allow the microphone and download a speech model. Never ask for, type, store, or relay my Anthropic API key or any one-time code. I enter those in Dum myself.
8. If a step fails, stop and show the exact error and the next command.

The prompt asks the agent to stop before sudo, the Xcode license, sign-in, 2FA, or writing outside the folder you choose. Never give an agent your password, API key, one-time code, recovery code, or security key. Review its commands like any other shell command.
