Installation

Have your AI install it ↓

Requirements

  • macOS 13 or later, on Apple Silicon or Intel.
  • Voice needs macOS 14 or later on Apple Silicon. Everything voice does also works from the keyboard.
  • A backend to power Dum. Either your own Anthropic API key for Claude, or models running on your Mac in Ollama or LM Studio. Claude takes only an API key, in every build. See who powers Dum.

The app carries its own Claude Code. You don't install anything else to use Claude.

Download

There's no public release of this version yet. Build it from source below.

Test builds come out of the desktop macOS workflow on pushes to main. They're ad-hoc signed and not notarized, and only signed-in GitHub accounts can download them. The older test prerelease on the releases page predates zones and doesn't match these docs.

First run

  1. Open the DMG, drag Dum into Applications, and launch it.
  2. If macOS blocks it: System Settings → Privacy & Security → Security → Open Anyway.
  3. Dum's window opens by itself. macOS asks for Screen Recording permission, for Dum's look. If you say no, Dum looks at app switches and saved files only.
  4. Answer What are you trying to learn? That becomes your first zone.
  5. Click Who powers Dum? and pick a backend, Dum's model, the helper and the look model. Then Dum and the Wizard start goal alignment for your first zone.
  6. From then on, click the floating circle, or press ⌘⇧D from anywhere, to open or hide Dum's window.

Dum is a small floating circle on your screen. There's no Dock icon and no menu bar icon. Drag the circle wherever you like.

Build from source

Prerequisites

  • A Mac with macOS 13 or later
  • Node 22.6 or later
npm install
npm run desktop            # build Dum and launch it from the checkout
npm run desktop:mac        # package the DMG and ZIP, with voice and the focus helper

Every build, yours or a released one, connects Claude with your own API key only.

npm run desktop runs without Dum's two native helpers, so there's no voice, no noticing app switches, and Esc can't hand focus back to the app you were in. Packaging builds them: the focus helper on any Mac, voice only on Apple Silicon, which needs Xcode, cmake, and Rust with the aarch64-apple-darwin target.

The checkout also starts on Linux. That's for development and testing only; Dum is a Mac app.

Let a terminal LLM set it up

Prefer to paste one instruction into the terminal agent you already use? This walks it through building Dum from source and launching it, checks each step, and stops when it needs you.

paste into your terminal LLM 
Set up Dum from https://github.com/hub-ry/dum-intern for me: build the Mac app from source and launch it.

Work one step at a time. Check the result before continuing. Ask me before:
- using sudo or installing anything system-wide
- opening a browser for any sign-in or completing 2FA
- entering, copying, storing, or relaying passwords, API keys, one-time codes, recovery codes, or security keys
- writing outside the folder I give you
- changing an existing project or deleting anything

1. Check that this is a Mac on macOS 13 or later, and check my Node version (22.6 or later is needed). If it isn't a Mac, tell me Dum is a Mac app and stop. If Node is missing or too old, ask me before installing it.
2. Ask where I want the repository. Clone it there if it is not already present.
3. In the repository, run `npm install`.
4. Run `npm run desktop`. It builds Dum and launches it, and keeps running until I quit Dum. Dum shows up as a small floating circle with its window open, not in the Dock or the menu bar.
5. Tell me to finish setup in the app myself: answer the Screen Recording prompt, answer "What are you trying to learn?", then click "Who powers Dum?" and pick a backend. Never ask for, type, store, or relay my Anthropic API key or any one-time code. I enter those in Dum myself.
6. If a step fails, stop and show the exact error and the next command. At the end, print what's left for me to do and wait.

The prompt asks the agent to stop before system changes, sign-in, 2FA, or writing outside the folder you choose. Never give an agent your password, API key, one-time code, recovery code, or security key. Review its commands like any other shell command.
